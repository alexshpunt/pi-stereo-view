# Stereo View for Herdr

This experimental mod shows Pi's Conversation and Activity histories in independently scrolling native panels. Pi owns the editor, dialogs and widgets. Editor-slot dialogs appear with history, and overlays are projected over it. Pi's picker placement preference controls whether its windows appear with combined history, full-width Activity or the split panels. Widgets from above and below Pi's editor share a strip below history, above the composer. Keyboard input and pointer movement, wheel, and left, middle and right button gestures go to their live Pi components. When a component does not handle the wheel, the projected surface scrolls instead. The panels follow new output until you scroll away; scrolling back to the end resumes following. While a panel is not following, a "Jump to latest" control floats over its bottom edge (tooltip "Jump to latest (End)"); it and the End key jump straight to the newest line and resume following. The toolbar controls layout and panel settings. Find searches the corresponding panel. The terminal remains available as a fallback.

History rows are terminal cells, drawn in the terminal's own font, size and row height (`font`, `font_size` and `terminal_line_height` of the Herdr settings, JetBrains Mono at a fixed row height when the layout names none) on the terminal's background, so every row is as many cells wide as the panel holds, Pi wraps at the panel's edge and the same turn takes as many rows as in the terminal view. A block's background (a user message, a tool call) spans the whole row, gutters included; the turn's colored bar stays one cell. Pi draws `[Go to] [Copy]` in the last row of each block; the mod leaves that row blank and shows the two as icon buttons, with tooltips, at the right edge of the block's first visible row while the pointer is over the block. A button presses the control Pi drew, so Pi does what a click on it does; Copy shows a check mark for a moment. Where two columns cannot hold 40 cells each, the panels stack as rows instead, and the layout button is dimmed with a tooltip saying why; the saved layout choice is untouched and applies again when the pane is wider.

The mod renders terminal image placements as native images. It fetches their data from the originating Pi in bounded chunks, verifies it locally and keeps decoded images in `data/stereo-view/images` under the Herdr app home. Each mod runtime uses a separate image directory; subsequent runs remove directories owned by processes that have exited. Files from the older shared cache are left in place because another app may still use them. Node.js must be on the app host's PATH and on the Pi terminal machine's PATH. When an image cannot be loaded, its panel shows a placeholder; the terminal remains available.

Switching a pane between GUI and TUI is one frame. Herdr starts the view's copy the first time the pane shows its GUI and keeps it alive afterwards; while the pane is in TUI mode and its tab is on screen the copy keeps its state and history pages current every 2.5 seconds (every 0.7 seconds while shown), so the next switch has content at once. A new copy draws only its background until the bridge's first state arrives, then the real layout; it starts from the cell and panel sizes the last copy measured. When a panel's width changes (window or divider drag) its rows stay on screen and are read again at the new width at once, instead of the panel going blank until the next poll.

Install the `stereo-view` mod folder under the Herdr app's `mods` folder. In a Herdr App with pane views, switch the Pi terminal pane to GUI to show Stereo View in place. In older Herdr versions, open the Stereo View app for the running Pi terminal or put it beside the terminal with `app.beside`. Automatic app-tab opening is disabled: the running App does not expose a read-only capability signal to distinguish pane-view support from older versions. Manual app opening remains available.

The mod expects `origin` (or `terminal`) to identify the Pi terminal. Its bridge label carries version 1, the Pi PID and a socket path matching `/tmp/stereo-XXXXXX/s`, where each X is an ASCII letter or digit. The PID must still be the terminal's root or foreground process. The socket protocol uses one UTF-8 JSON request and response, each terminated by a newline. The fixed Node client runs on the terminal's machine; it does not execute a label-provided command or script. Requests are limited to 4 KiB, responses to 4 MiB and connections to three seconds. The mod retains bounded row pages and fetches around each viewport. The terminal remains available if the bridge is missing or fails.
